# agent 通读校对

proofreading 的前移：发现环节从「维护者阅读时记下」换成「子 agent 按块通读」，判定口径与规则落地不变。**开工选卷先查 `status.md`（各卷 AI 校对状态；文件在本 skill 目录下，即 `.agents/skills/agent-proofread/status.md`，不在仓库根）。选卷口径：优先「上游已校对、本项目未校对」的卷做二校**——上游自 2026-09 起从头全量通校、预期自行覆盖全卷，本项目价值转为二校兜底（产出实证见经验段重合度条目）；「本项目校对先于上游通校」的卷（S1_01~07）待上游通校落地后先用 `scripts/proofread_overlap.py` 重合复核、清理失效规则，其后亦可排二校通读——目标只剩双漏尾部（两轮都未发现的缺陷），优先级次于全残存池卷。

## 判定依据（指针，不复制进本仓库）

- 规范正文：`index-X/docs/translation-spec.md`——尤其「四、语义与信息」（哪些必判缺陷）与「六、证据边界」（防误报）。
- 已裁定索引：`index-X/.agents/skills/translation-term-unification/SKILL.md` §六 + `index-X/docs/maintenance-records/`——**开工前必读**，已裁定锚点不得翻案。

## 流程

### 1. 切块分派子 agent（全文对照）

- `uv run python scripts/agent_proofread/plan_chunks.py <卷>`：把整卷正文切成 ≤10 块（delegate_task 并行上限），主区间无缝拼接、前后 ~10 行重叠上下文。包装页（Cover/Illustrations/Information 等）自动跳过。
- **中日逐行对照文件**（bw_aligned pass 卷）：plan_chunks 为每块生成 `.triage/proofread_chunks/<卷码>/chunk-NN.txt`——每物理行一对 CN（Y 剥标签，ruby 注音连写）/JP（对齐单元同行剥标签），行号即 Y 物理行号（`check_y_jp_alignment` 门禁保证行结构一致）。派生产物，每轮开工重新生成；对齐缺失/行数不等的单元（PAIR_RULES 豁免等）段内只列 CN 并标注「※无行号对齐」；非 pass 卷自动退回旧形态（goal 直指 xhtml 行区间 + locator 核对，模板【无行号对齐卷模式】节）。块尺寸默认 1.2 万中文字符/块（对照形态输入近翻倍；未对齐卷仍 1.5 万）；大卷（>12 万字符）给 `--max-chunks 14` 维持块尺寸——并行上限是配置项（当前 30），14 块单波可行（S5_01_01 实证）。
- 分派参数以 plan_chunks 输出为准直接复制：goal 用逐块 goal 行，context 与 output_schema 用末尾印出的全块共用版（context 是短指令，让子 agent 自 skill_view 加载 `templates/chapter-agent-prompt.md` 并替换 `{{VOL_PREFIX}}`）。**禁止把 4.5KB 模板全文 ×N 块手工抄进调用**——长重复 JSON 抄写会塌缩漏字段（S1_04 事故：context 连续 4 次漏写，steer 才救回）。一次调用并行分派全部块。
- 子 agent 的日文依据随对照文件下发（JP 行照抄进 jp_evidence，误译/漏译类必附）；`scripts/proofreading_locate.py` 只剩两用途：「不一致」类的全卷计数、无对齐段/失配区/非对齐卷兜底——模板要求**批量一次跑完**（试跑教训：一词一查会让单 agent 拖到 40+ 轮）。
- 块尺寸与额度：瓶颈只在 token（任务 24h 可跑），不按墙钟定方案——Kimi 输出速度随服务拥挤度可有 3× 波动，墙钟在方案间不可比。块越大单块分析轮越长（输出 token 集中），3.8 万字大章曾是最重块——大块有超 5h 窗风险，预期超窗就切细或跨窗。缓存：TTL 随轮刷新，活跃子会话不会全价重付。

### 2. 三层复核（子 agent 产出是自报，不复核不落规则）

1. **机械验证**：把各子 agent 返回的 findings 数组合并为一个 JSON 文件（保留 file/line/quote/jp_evidence 等字段），跑 `uv run python scripts/agent_proofread/verify_findings.py <卷> findings.json`——中文引文逐字验证（剥标签容差）、日文依据语料验证、X/Y 比对。块间重叠上下文行若被多个子 agent 重复上报，按 (file, line, category, quote) 去重。
2. **X≠Y 归因**：`x_same=false` 的条目查 rules/——良性归一化（如 塑胶→塑料）按上游问题处理；**规则改坏的是规则回归**（案例：`_common` 安心感→安全感 把 X 的正确译法改错），落分卷规则压回，不回改通用规则。
3. **人工判定**：误译高置信条目逐条回原文终判；警惕**模式性误报**——单章看似衍字、全卷实是统一体例（案例：四章标题均带人称「她/他」，单报一章即误报）。**无法确定即不采**：本流程不留「存疑交人工」，agent 判定不了的条目按不采忽略并在 commit body 登记理由（含双关改写方案、体例口径冲突、首现写法存疑等）。

### 3. 落规则

- 候选规则写 TSV（`旧<TAB>新<TAB>注释` 三列，注释含原文依据；旧串为 X 侧 xhtml 逐字，ruby 标签内联）。
- `uv run python scripts/agent_proofread/apply_rules.py <卷> candidates.tsv [--replace 旧串]...`：归属计数（全语料命中跨卷即报错交裁决——**裁决口径：默认顺带一并改**，各命中点逐条回原文确认同译无害后提升 _common 或逐卷落规则；仅当别卷命中不宜改时才加长旧串限本卷）、正则守卫、双模拟，全过才写 TSV。
- 重跑 `uv run python scripts/sync/x2y.py`，`--verify-y` 终验；`git diff` 应为纯行内替换（+N/−N 相等）。
- rules/ 与 EPUB/ 同一 commit：`fix: 校正 <卷标识>（N 处文本修订）`，body 附全量 `旧→新`。
- **登记 `status.md`**（本 skill 目录下同名文件）：更新该卷「本项目」列为日期（提交号，修订处数），随本批改动一起提交。

## 经验

- 子 agent 引文跨 ruby 标签或跨行：raw 不匹配≠编造，verify_findings 已含容差；仍不符才算编造。
- 对照文件（`.triage/proofread_chunks/`）是派生产物：源为 Y 产物与 bw_aligned 对齐单元，行结构一致由 check_y_jp_alignment 门禁保证；每轮开工重新生成（规则落地后 Y 会变）。子 agent 的 quote 是剥标签文本（注音连写形态），verify_findings 剥标签容差段负责匹配；jp_evidence 照抄 JP 行即可过语料验证（对齐语料已并入）。发现连续多行 CN/JP 不相关按行号失配处理：该区域退回 locator 兜底并在 stats.note 登记。
- 归属计数是子串误伤探测器（S5_01_01 实证）：候选规则的预期命中数与归属报告不一致时，逐处看命中形态再定旧串——「运算→演算」预期 3 实得 5（「搬运算」子串 +「逆向运算」系 逆算 锚，两处正用）；「恩、」全语料 3 命中含「卢恩、」「西格恩、」子串误命中，真错字仅 1 处。错字/短词规则先全语料看命中形态，有正用就带上下文加长旧串。
- 全文对照流程首跑实测（S5_01_01）：13 块子代理 0 编造（jp_ok 全真）、locator 用量大跌（jp_lookups 0~2/块）；归属验证拦下的 4 条跨卷规则按「别卷命中未经逐条核对」逐条带上下文限卷落盘（魔术/线缆/运算）或手写落盘（「——」独行、半角括号转义）。
- 原文仓库部分文件的读音写在 `<rt>` 之外（如 安堵あんど）：verify_findings 已用读音容忍正则兜底（仅兜底救回的条目打 jp_flex 标记）；仍 jp_ok=False 的是拼接/改写/引号差异等非逐字引文，取 locator 原文命中人工核一眼再判，勿直接判编造。
- 既有规则可能与新规则抢同一文本：长规则取代时用 `--replace` 删旧短规则（案例：估计大概→估计）；分卷先于通用应用，顺序即真理。
- TSV 表头必须保留——丢表头 x2y 校验直接拒收（本流程犯过）。
- 子 agent 自报的「读了多少字/查了多少词」不可信，以脚本验证为准。
- 各脚本的卷参数接受卷目录全名或卷码（`S1_02`，全/半角括号形态亦可，唯一匹配）。
- 块尺寸（S1_03/S1_04 实证）：并行上限是 `delegation.max_concurrent_children` 配置项而非硬约束。长上下文降质有实例（16k 块漏掉区间内七大词簇，复核层兜底抓获）；8k 小块 ×15 发现密度不降（S1_04 采纳 47，与默认块各卷持平）但额度高 ~40%（0.67 vs 0.37~0.49 窗/卷）——质量相当下用默认 14k 块。块尺寸按发现质量与额度定档，不按墙钟（Kimi 输出速度随拥挤度 ~3× 波动，方案间墙钟不可比）。
- 子 agent 低效模式（模板可防）：①search_files 第一把拿 count 格式又重跑拿 content，白烧一轮——提示词应指定带内容的输出；②定位器清单没收全候选，转用裸 grep 进 index-jp 逐文件翻（14 轮摸结构+grep）——回查词宁滥勿缺全进清单，补查也用定位器第二轮，不裸 grep。
- 候选规则的新串要按「管道终态」写：遇带上下文条件的通用规则（如 `_common` 152 `由于(?=…所以)→因为`、154 删「的关系」），新串若仍含其触发模式，通用规则会在分卷规则之后再改一遍，双模拟终态断言必失败——把触发上下文（但/所以、因…的关系）纳入旧串并在新串直写终态（案例：但由于…流动，所以→但因为…方向，所以；因角度的关系→因角度关系）。
- delegate_task 分派事故（S1_04 犯过）：主代理连续多次调用漏写 tasks 项的 `context`（响应回显只有 goals，发现不了），子 agent 裸 goal 起跑。根因是手工抄写 15×4.5KB 重复 JSON 致字段塌缩；根治是把机械抄传输收进脚本——context 短指令化（子 agent 自载模板）+ plan_chunks 直印 goal/context/output_schema 三参数（见流程 §1）。「分派后读一只 live transcript 的 kickoff 验证」仍是兜底探测；补救用 `delegate_task(action='steer')` 逐只补发指令可行（子 agent 多会自行 skill_view 模板但不可依赖）。
- verify_findings 大面积 jp_ok=False 先怀疑引用 artifact 而非编造：定位器输出的（partXXXX.html）来源标注、多句「／」拼接、中文解说混进 jp_evidence 都会判负（模板已补「jp_evidence 只写日文句子本身」）。复核姿势：剥标注、按 ／ 切段、core 子串逐条探测（S1_04：49 条 jp 证据初验仅 6 过，清洗后全部坐实，0 编造）。
- 子 agent final answer 在 live transcript 里被截断（~625 字符）；合并 findings 从 `state.db` 的 `async_delegations.result_json` 提取完整 summary（结构 `{results:[{summary}]}`），勿手抄。注意是 hermes 根目录的 `state.db`，不是 `shared-state.db`（无此表）——按文件名后缀选库会先命中后者。
- 合并去重键要含 category：同一行可报多条不同类发现（S1_05 159 行误译+错字共用同引文），按 (file, line) 去重会误删真发现；用 (file, line, category, quote)。
- 一条规则的旧串可在卷内多行命中且双模拟照过（S1_05「叹了一口气→叹了口气」命中 2 行）：提交前数 git diff 行数与规则数是否吻合，多命中的行要逐条回原文确认同译无害再登记进 body。
- 各卷产出参考（发现/采纳/不采；额度数据见下条成本实测）：S1_01（按章分派旧方案，11 万字符 6 块）56 发现、误报 <15%，子 agent 原文回查接近遇疑必查（全卷 164 词）。S1_02（切块新方案，12 万字符 9 块）54 发现采纳 55 条规则（57 处修订）、否决 1 条。S1_03（11.3 万字符 8 块）54 发现采纳 71 条规则（70 处修订）、不采 4 条。S1_04（8k 小块 ×15，11.3 万字符）54 发现采纳 47 条规则（48 行修订）、不采 7（低置信 4 + 无法确定 3），含一次分派事故（context 漏写）。S1_05（14k×9，12.6 万字符）48 发现采纳 47 条规则（48 处修订）、不采 3（原作矛盾 1 + 原文双轨刻意对应 1 + 口语可通 1）；双模拟不挡「一规则多行命中」，diff 行数须与规则数对账。S1_06（14k×8，11.7 万字符）54 发现采纳 50（60 条规则，62 处修订：一规则 5 命中 + 两规则同行 2 处，diff 行数对账吻合）、不采 4（忠实原作笔误 1 + 卷内体例一致 1 + 原文双层写法 1 + 跨卷惯用 1）。S1_07（14k×9，13.0 万字符）48 发现采纳 41（47 条规则：本卷 41 + _common 5 + S2_17 1，62 处修订：piú 一规则同行 2 处）、不采 7（原文双层写法 3 + 原文体例 1 + 原文有据意译 1 + 无法确定 1 + 异质惯用词 1）。S5_01_01（全文对照首跑，12k×13 单波，15.3 万字符，上游已校卷的二校）71 发现采纳 97 条规则（分卷 93 + 通用 4，157 处修订）、不采 3 类 6 条（结构体例伪信号 4 + 规范合规 1 + 原文泛指 1）。
- 成本实测（state.db 会话直查，7 卷全量）：子代理 in+out 0.9~1.2M tokens/卷，含主代理 orchestration 共 1.2~1.6M；按费率卡折 credits ≈ 440~800/卷 = **0.37~0.67 个 5h 窗/卷**（S1_04 最高，含分派事故浪费 ~40 credits）——「按百万 token/卷估」只是规划上界，实测约半。cache_read 6~10M/卷但近免费（<10 credits），成本大头是输出 token。全量对照增量测算（S1_01 基准：JP 侧 14.6 万字符，双文本输入仅 +~21 credits 可忽略，增量全在输出）：双文本通读 ≈ 0.5~0.65 窗/卷（仍可单窗）；逐行强制对照+复核（≈上游形态）≈ 0.7~1.8 窗/卷，超单窗需切细或跨窗。实测口径：按卷归集会话语法见 hermes-usage-stats（parent_session_id 分批 + 批次分钟窗）。**全文对照流程实测**（S5_01_01，15.3 万字符，12k×13 单波）：子代理 in 7.86M / out 448k tokens，5h 窗水位实测 +73.0%（含主代理复核层与定位器）≈ 0.73 窗/卷——与「双文本通读 0.5~0.65 窗/卷」测算同量级（本卷字符数高于历史均值约 25%），单窗可完成。
- 模式性误报新案例（侧/阵营）：「科学侧/魔法侧」与「科学阵营/魔法阵营」同行混用看似卷内不统一，实是日文原文 サイド（术语层）与 側（汉字普通词层）双层写法，X 分层忠实原文——判「不一致」前必须回 ../index-jp 查锚点的日文写法是否本身分层，已裁定分层口径（サイド→阵营、側→侧）不得翻案。S1_07 再现（科学侧×2、魔法侧×1 锚点全为汉字 側）；同类新形态：硬币袋/金币袋（S1_07）看似译名不一，实是原文 硬貨袋/金貨袋 自带区分（金貨袋仅马太象征解说 1 处）——「不一致」候选须把卷内各写法的日文锚点都查一遍，原文自带区分即驳回。对照形态下锚点写法就在 JP 行，先看对照行再决定要不要查卷内分布。
- 合并 findings 的两个工具坑：①JP-only 关键词进 proofreading_locate 是在 X 中文语料计数（必为 0），查日文锚点写法直接 grep ../index-jp 对应卷；②子 agent 不遵守 output_schema（散文+JSON 混排）时从首个 `{` 起 json.raw_decode 提取即可救回，不必打回重跑（S1_06 task-2 案例）。
- 校对范围不限本卷（用户口径）：顺带发现的别卷同一问题一并改掉——归属计数报错交裁决时默认走「跨卷一并改」：各命中点逐条回原文确认同译无害后提升 _common（如 新世代兵器→次世代兵器 归一 S1_03/05/06 共 7 处）或逐卷落规则；只改本卷是例外而非常态。以「系列惯用」为由不采前先拆解命中构成：S1_06 缩图案 12 处 = 3 误命中（压缩图片）+5 术式专名（缩图巡礼）+2 正用（照片缩图）+1 比例地图（战场缩图）+1 真候选（世界的缩图→缩影），拆完所谓系列惯用只剩本卷 1 处可改。
- 港台用词归一已立政策（_common 13 条：电动游乐场/电动脑/打电动/公车/机车摩托义/记忆体/硬体/的士/电玩）：后续校对遇港台用词直接报缺陷落规则，不得再以「卷内体例一致」为由不采（S1_06 电动脑案被政策推翻）；新添候选先全语料计数+逐条语境排查（士兵/软体动物/水晶片式误报），并与 _common 既有规则查重（荧幕→屏幕早已在）。
- 子代理的证据侧只有 Y 与日文原文，X（规则应用前的上游文本）不是证据：定位器已加 `--side y`（Y 侧计数+Y 上下文+JP），模板固定使用；默认 both 保留给维护者阅读校对（规则旧串截取与归属计数需要 X 侧）。主代理复核层 verify_findings 的 X/Y 比对不受影响。
- 错字短旧串防「正用」误伤（S1_07 头捶案）：「头捶→头槌」若作旧串会把 S2_01「用拳头捶在墙上」的正用子串绞成「头槌在墙上」——两字错字规则先全语料看命中形态，有正用就带上下文加长旧串（愤怒的头捶）。归属计数会挡，预查省一轮裁决。
